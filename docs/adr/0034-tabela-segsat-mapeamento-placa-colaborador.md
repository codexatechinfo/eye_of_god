# ADR 0034 — Nova tabela `segsat` (mapeamento placa ↔ colaborador)

## Contexto

A integração com a API de frota SEGSAT (posição/velocidade/ignição dos veículos) ficou parada numa
conversa anterior desta sessão porque a API não tem nenhum campo de motorista — só a placa (ver
ADR anterior sobre a investigação da API SEGSAT, feita antes desta). Usuário forneceu a planilha
`Relacao de Veiculos Empresa.xlsx` (122 veículos, 1 aba), com a relação placa↔colaborador que
faltava, e pediu pra criar uma tabela nova pra guardar isso — sugeriu o nome "segsat".

### Verificação feita antes de desenhar a tabela

- Cruzamento ao vivo confirma o campo certo pra ligar as duas fontes: as 122 placas da planilha
  batem **100%** com o campo `nm` da resposta real de `GET /devices` da SEGSAT (não com
  `uid`/`uid2`, que a documentação descreve como o IMEI mas que na prática vêm `undefined` em quase
  toda unidade real — achado ao vivo, a doc não bate com o comportamento real aqui).
- Planilha tem 4 veículos sem colaborador atribuído (campo `Colaborador` = `"-"`) — gravados como
  `NULL`, não como o texto literal.
- Cruzando contra `ativos_inativos`: 66 de 119 colaboradores da planilha (55%) batem por nome
  exato. Mais baixo que o Scalefusion (ADR 0033, ~70%) — não investigado a fundo aqui, fora do
  escopo do pedido (só criar a tabela), mas registrado pra quando a coleta de posição em si for
  construída.

## Decisão

Réplica exata da estrutura da planilha, mesmo padrão de toda tabela de referência do projeto
(`id` + `empresa_id` com RLS `isolamento_empresa`):

```sql
CREATE TABLE public.segsat (
  centro_custo character varying(255),
  placa character varying(20) NOT NULL,
  modelo_veiculo character varying(100),
  versao_modelo character varying(100),
  ano_modelo integer,
  franquia_km character varying(50),
  colaborador character varying(255),
  filial character varying(100),
  locadora_veiculo character varying(100),
  rastreador character varying(100),
  numero_rastreador character varying(30),
  id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  empresa_id uuid NOT NULL REFERENCES public.empresas(id)
);
```

`numero_rastreador` (IMEI) como texto, não número — é identificador, não quantidade (mesmo
raciocínio já aplicado a `livro`/`etapa`/UC em toda outra tabela do projeto). Índice único em
`(empresa_id, placa)` — cada placa aparece uma vez só na planilha, e é a chave de junção contra a
API. Aplicado direto via `docker exec supabase-db psql`, sem framework de migration (mesmo caminho
de sempre neste projeto).

Importação foi um script descartável (`importar_segsat.js`, não commitado — mesmo padrão da ADR
0024 Adendo 2), lendo a planilha convertida pra CSV UTF-8. `DELETE` + `INSERT` completo (não
upsert) — carga única de 122 linhas, sem necessidade de reimportar incrementalmente ainda.

### Fora de escopo desta rodada

Só a tabela e a carga inicial foram pedidas. Não criado ainda: job de coleta de posição da SEGSAT
em si (equivalente ao `scalefusionJob.js`), nem uso desta tabela em qualquer tela — isso depende de
decidir a mesma coisa que já foi decidida pra Scalefusion (histórico completo vs. só posição atual)
quando o usuário pedir.

## Verificação

- `\d+ segsat` confirma estrutura, índice único em placa, RLS forçada com a policy padrão.
- Import: 122 linhas gravadas, 4 com `colaborador IS NULL` (as 4 sem atribuição na planilha),
  acentuação preservada (conferido: "Foz do Iguaçu", "Campo Mourão").
- Cruzamento ao vivo `segsat.placa` × `GET /devices` da SEGSAT (`nm`): 122/122 batem.
- `BACKEND/test/isolamento_tenant.test.js` ganhou `segsat` na lista de tabelas testadas — suíte
  completa (16 testes) passa.
